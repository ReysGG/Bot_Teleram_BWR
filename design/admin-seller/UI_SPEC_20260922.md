# UI specification admin + seller lokal

Sumber review layout: sesi ChatGPT Chrome 22 September 2026.  
Scope: admin dashboard, inventory, stock detail, seller review, seller dashboard,
products, draft editor, sales, balance, withdrawals.

## Theme lock

Only use these semantic tokens:

```css
--paper: #f4eddf;
--surface: #fffdf8;
--ink: #141414;
--muted: #68645e;
--border: #d8d0c3;
--orange: #f15a24;
--green: #2f7d4a;
--amber: #b66a18;
--red: #b74432;
--disabled: #aaa397;
```

Grid background is 3–5% opacity on the outer canvas only. Tables and forms use a
plain surface. No blue, purple, neon gradient, or third-party runtime font.

## Shared shell

- Desktop: 232px sidebar, 64px top bar, 32px page padding, 1360px content max.
- Mobile: 16px page padding, 12px card gap, 24px section gap, 44px minimum tap target.
- Display headings use the existing serif stack. Body and UI use the existing
  system sans stack.
- Use reusable `AdminShell`, `SellerLayout`, `Panel`, `MetricCard`, `FilterBar`,
  `StatusBadge`, `EmptyState`, `LoadingSkeleton`, `ConfirmSubmitButton`, and
  `Pagination` components.

## Page layouts

| Page | Desktop | Mobile | Required states |
| --- | --- | --- | --- |
| Admin dashboard | 4 summary metrics + 8/4 operational split | Metrics become horizontal cards | loading, zero backlog, warning, error |
| Inventory overview | filter/search toolbar + table + right health summary | toolbar stacks; rows become cards | available, reserved, banned, empty |
| Inventory detail | identity header + 8/4 file/health split | metadata first, actions bottom | encrypted, checking, healthy, banned |
| Stock takeout | warning panel + explicit confirmation + audit preview | one-column confirmation | eligible, blocked, processing, success |
| Seller review | queue table with seller/status/date + detail drawer/page | review cards with sticky action footer | submitted, rejected, approved, stale revision |
| Seller dashboard | 4 metrics + sales/stock panels | metrics stack, charts become summaries | invited, active, suspended, empty |
| Seller products | search/filter + draft/live cards | one card per product | draft, submitted, rejected, live, paused |
| Seller draft editor | 8-column form + 4-column review panel | form then review summary | unsaved, saving, validation error, submitted |
| Seller sales | paginated table with settlement status | cards with gross/net/status | pending, available, held, refunded |
| Seller balance | pending/available/held ledger buckets | stacked buckets + ledger rows | zero, negative debt, hold, error |
| Seller withdrawals | request list + payout account context | cards and timeline | requested, approved, paid, failed, ambiguous |

## Rating placement

- Product rating belongs on product detail and order item review card.
- Seller rating belongs on seller profile/dashboard summary and completed order
  seller review card.
- Never merge product and seller averages into one score.
- Show count and average separately; use orange stars/icons and ink text.

## Interaction rules

- Destructive/financial actions require confirmation, disabled processing state,
  and stable notice/error code.
- Empty states explain the next action; skeletons preserve final layout width.
- Tables never overflow horizontally on mobile; convert rows to labeled cards.
- Assets are local and optimized. No per-card third-party image request.
